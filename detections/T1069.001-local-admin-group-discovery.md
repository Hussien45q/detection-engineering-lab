# T1069.001 – Local Administrators group discovery

| Field | Value |
|---|---|
| MITRE ATT&CK | [T1069.001 – Permission Groups Discovery: Local Groups](https://attack.mitre.org/techniques/T1069/001/) |
| Wazuh rule | 100108 (level 8) |
| Log source | Sysmon Event ID 1 – Process creation |
| Status | ✅ Detected |

## What the attacker does
Attackers list the members of the local **Administrators** group to find out which accounts are worth stealing credentials from, and whether their own account is already an admin. This is standard reconnaissance in ransomware playbooks and penetration-testing tools.

## How I simulated it
```powershell
net.exe localgroup administrators | Out-Null
```
Read-only and nothing to clean up.

## What the logs showed
Sysmon logged **two** process-creation events: `net.exe localgroup administrators` and, a moment later, its child `net1.exe localgroup administrators`. On modern Windows, `net.exe` hands the real work to `net1.exe`.

## The detection logic
The rule fires when:
- `image` ends in `\net.exe` or `\net1.exe` (`net1?\.exe`), **and**
- the command line contains `localgroup` followed by `administrators` (optionally quoted).

## Result
✅ Rule 100108 fired **twice** at the same second, once for `net.exe` and once for `net1.exe` (test run 2, 4 Oct 2026).

## False positives and tuning
- **Duplicate alerts:** because of the net → net1 hand-off, every run produces two alerts for one action. Options: match only `net1.exe` (it always runs), or keep both and group them in the dashboard. I kept both. If an attacker calls `net1.exe` directly, a `net.exe`-only rule would miss it.
- **Admin activity:** helpdesk staff do run this command. The level (8) is a "review" alert, not an incident. Tuning would be an allow-list of admin workstations or accounts, after reviewing a few weeks of data.
